## Inventory and notices

- `dependency-inventory.json`: exact versions, declared licenses, installed versus
  optional/uninstalled state, runtime/development classification, npm artifact
  hashes and Python source-distribution locations. 372 locked artifacts checked;
  326 installed. Python runtime classification follows the locked dependency graph.
- `THIRD_PARTY_NOTICES.txt`: verbatim installed license/notice files, grouped by
  package and version. This includes build/test dependencies for review.
- `frontend/public/THIRD_PARTY_NOTICES.txt`: frontend dependency notices copied
  into every production build.
- `frontend/dist/BUNDLED_LICENSES.md`: generated by Vite from the actual bundled
  module graph. Retain this file with any distributed frontend build.
- `frontend/public/fonts/*-LICENSE.txt`: original font-package notices, also
  copied to the build. Fonts are served locally, never from a CDN.

The `react-remove-scroll-bar` 2.3.8 npm artifact omits its MIT text. The upstream
project's published MIT notice, retrieved from its `master/LICENSE` on 2026-10-25,
is preserved in `licenses/react-remove-scroll-bar-2.3.8.txt` and included in the
frontend aggregate notice as supplemental attribution. Package source revision,
verified with npm `gitHead`:
`b3b1287aad81def2e2ae707274b74531b61ddbaf` in the upstream
`theKashey/react-remove-scroll-bar` repository. That revision also lacks the license
file; the saved notice is from the current upstream project, not claimed as a file
from the historical npm artifact. The installed manifest explicitly declares MIT.
No package source was altered.

Regenerate the inventory and notices after installing frozen dependencies:

```powershell
.\backend\.venv\Scripts\python.exe scripts\audit_dependencies.py
```

The audit is offline and rejects unknown license identifiers and unapproved MPL
families. It verifies installed versions against the lockfiles; it does not
replace legal review of a future installer or independently audit every upstream
binary's internal components. The isolated build backend is hatchling 1.32.4
(MIT), pinned in `pyproject.toml`; it is build tooling, not application runtime.

## Distribution boundaries and obligations

Phase 1 produces a frontend build and source checkout, not an installer. The
frontend includes React, router, Radix, Lucide and their bundled dependencies,
plus IBM Plex Sans/Mono and Source Serif 4 fonts. Preserve both generated notice
files and font licenses. The font packages are respectively 5.3.0, 5.3.0 and
5.3.1 under OFL-1.1; they are unmodified, not sold separately, and not relicensed
under Apache-2.0. Source records:
[IBM Plex Sans](https://fontsource.org/fonts/ibm-plex-sans/about),
[IBM Plex Mono](https://fontsource.org/fonts/ibm-plex-mono/about),
[Source Serif 4](https://fontsource.org/fonts/source-serif-4/about).

MPL tools are executed while building/testing and are not imported into the
application frontend or production Python dependency graph. Generated CSS is
application output; the Lightning CSS engine/native binary is not bundled.
FastAPI brings `opentelemetry-api` 1.45.1 (Apache-2.0); there is no telemetry SDK,
exporter, collector configuration or application telemetry integration.

If a future deliverable includes a development environment, native build tools,
test bundles or MPL-covered libraries, preserve their notices, supply the exact
corresponding source under MPL-2.0, and tell recipients where to obtain it. Do
not rely on an unverified moving upstream branch. Python source archives for
the installed certifi/pathspec versions are recorded in the inventory; upstream
source projects for the other families are
[Lightning CSS](https://github.com/parcel-bundler/lightningcss),
[axe-core](https://github.com/dequelabs/axe-core), and
[axe-core integrations](https://github.com/dequelabs/axe-core-npm).
Before such redistribution, verify the exact release source and preserve a
source archive with the distributed artifact. No such toolchain redistribution
is performed in Phase 1.

MPL requires covered source and notices to remain available when covered code
is distributed, while allowing separately licensed application files in a larger
work. See [MPL 2.0 sections 3.1–3.4](https://www.mozilla.org/en-US/MPL/2.0/)
and [Mozilla's distribution FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/).
No dependency license is replaced by the application's Apache license.

Other reviewed licenses are MIT, MIT-0, ISC, BSD-2-Clause, BSD-3-Clause, 0BSD,
Apache-2.0, PSF-2.0, BlueOak-1.0.0, CC0-1.0, CC-BY-4.0 and OFL-1.1.
`caniuse-lite` is build-only CC-BY-4.0 data; its bundled attribution/license text
is preserved in the aggregate notices. Any future redistribution must retain
applicable attribution and license references. Future dependency changes must
rerun this audit; GPL/AGPL/LGPL or new copyleft additions need separate approval.
